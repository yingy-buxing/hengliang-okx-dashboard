# 衡量：OKX 账户分析看板（本地版）

启动后访问 <http://127.0.0.1:4180>：

```sh
cd hengliang-okx-dashboard
python3 account-dashboard/server.py
```

macOS 也可双击 `启动看板.command`。在页面填写自己的 API Key、Secret Key、Passphrase，选择账户注册站点。只接受服务端确认的读取权限。API IP 白名单必须允许本机实际出口 IP。

## 本版功能

- 验证只读权限后展示当前交易账户权益、资产、资金账户、持仓及普通挂单数量。
- 自动分页获取最近三个日历月的成交、账单、历史持仓及资金记录，补齐历史日价格。
- 展示 USDT 永续合约已实现盈亏、手续费、资金费、币种贡献；现货、杠杆、交割、期权成交可在明细搜索和分页查看。
- 支持 USDT 线性永续净持仓模式的交易轮次和交易账户日净值重建。仅在样本与核对满足条件时显示胜率、夏普、回撤。混合保证金、交割、期权、强平、非 USDT 结算及无法复核的期初持仓，暂不显示历史风险指标。
- 净值剔除交易账户划转，按北京时间日收盘估值。资金账户和理财历史不计入净值；日内划转采用收盘估值。夏普无风险收益为零、日收益样本标准差、365 天年化，排除未结束日期。
- 每次连接或重新打开页面自动同步 API 近期记录；“同步 API”也可手动触发。同步按记录去重并保留过去已保存的数据，结果可导出 JSON。
- “数据与计算口径”中可同时导入手机导出的仓位快照、持仓历史、统一交易账单、资金账单、历史委托 ZIP 或 CSV。历史委托 ZIP 内附带的逐笔成交也会读取。检查文件中的用户 ID 必须与连接账户一致。只支持中文手机导出格式、UTC+8；未注明时区的历史委托按 UTC+8 解释。
- API 已查询区间内采用 API 记录，文件只补区间外历史。导出账单与 API 编号不总能直接匹配，因此使用日期窗口及成交编号去重；重复文件跳过。获取不完整时明确标注，不把文件混入该 API 区间。
- 盈亏与月份统计按所选分析日期汇总本机逐笔账单。日权益尝试从 API 与导入账单合并重建；夏普与回撤仅计算最近连续正权益区间，轮次胜率使用合并账单复核的完整轮次，开平仓均须在所选日期内。仓位历史、快照用于核对历史保证金模式与合约面值。
- 上次成功同步早于当前 API 三个月查询窗口时，登录显示可能缺口及日期；保留提醒，暂不自动补缺或认定已修复。
- 示例数据由程序生成，完全不使用工作目录内已有账户数据。演示场景不是完整真实账本。

## 会话和数据边界

仅监听 `127.0.0.1:4180`。认证由后端签名，请求限定固定 OKX 域名及 GET 接口；使用 TLS 校验且拒绝重定向。浏览器使用 HttpOnly / SameSite Cookie，服务端检查 Host、Origin、CSRF；静态资源使用 CSP，不加载第三方脚本。全局站沿用可用的 `www.okx.com`，美澳站为 `us.okx.com`，欧洲站为 `eea.okx.com`，参照 [OKX 官方文档](https://www.okx.com/docs-v5/zh/)。美澳与欧洲账户未做实盘验证。

每个浏览器会话独立保存在进程内存中。未勾选“记住此账户”时，密钥不写文件或浏览器存储，也不返回页面；断开连接、服务重启或最后一次用户请求后 30 分钟清除内存会话，GET 状态轮询不延长有效期，前台自动快照 POST 会维持会话活动，切到后台后快照暂停。勾选后，服务端在 macOS 通过 Security Framework 保存到登录钥匙串，在 Windows 通过 CredWriteW 保存到当前用户的系统凭据管理器，不经过命令行参数、不写应用配置文件。保存槽位为当前系统用户下的本项目一个账户；下次打开页面若没有活动会话，会自动尝试恢复并重新验证只读权限。主动断开不会马上自动恢复，重新打开或点击“连接已保存账户”可恢复。“忘记账户”删除已保存条目并断开当前会话；其他已连接浏览器会话仍按原规则失效。系统凭据存储拒绝访问或 API 失效时，保留保存项并显示错误，可以解锁后重试或忘记账户。同一浏览器共享 Cookie 的标签页共用账户。不要把本服务直接开放至公网。

历史采集在独立进程的权限 700 临时目录中完成，临时数据文件权限 600，任务结束后删除；有效历史记录和分析结果另存到项目下 `.account-data/history.sqlite3`，目录权限 700、文件权限 600，并已排除 Git。历史库按 OKX 账户身份及站点隔离，换 API 密钥仍使用同账户历史，不保存三项凭据。断开、忘记钥匙串账户及重启服务均保留历史库；下次验证同账户后继续使用。历史库是本机账户数据，未做数据库加密，保护由当前操作系统账户和磁盘承担。强制杀进程、机器断电等异常终止可能留下临时数据。本版支持可选的 macOS 钥匙串或 Windows 凭据管理器保存，没有登录系统或多人在线部署；在线版仍需要 HTTPS、用户登录及服务端访问控制。

`api.rtf` 不由网页自动读取。只有 `verify.py` 端到端检查脚本显式从旧客户端读取它，在本机提交并于最后断开测试会话；不打印凭据或金额。网页接入的凭据不会写回该文件。

## 复核

```sh
python3 -m py_compile account-dashboard/server.py account-dashboard/worker.py
python3 account-dashboard/verify.py
```

端到端检查需要先启动服务以及现有只读凭据文件；会发起真实只读查询。它检查会话隔离、CSRF、跨站限制、真实接入、历史分析及断开清理。前端可在不提供密钥的情况下用“先用示例数据体验”检查页面。

新增保存功能已通过 macOS 钥匙串写入、读取、更新、删除检查，以及 6 项保存/恢复和历史导入 HTTP 测试。浏览器隔离测试验证了勾选保存、断开保留、重载自动恢复、忘记后不再恢复；测试使用单独的假凭据和钥匙串条目，已清理。运行 `python3 account-dashboard/test_saved_account.py` 可重做这组测试，不访问 OKX、不保存真实账户。

本机历史库通过 4 项测试，覆盖 API 重叠优先、重复导入、事务校验、跨月保留、按成功同步时间判定缺口和失败不推进同步时间。运行 `python3 -m unittest discover -s account-dashboard -p "test_*.py"` 可复核。

### 合并历史净值（2026-10-05）

新增 equity_history.py：采用 API 优先的合并账单，检查导出文件声明区间与 API 覆盖窗口是否连续；以原始数量、成交价、余额变动和仓位余额变动重建现金、逐仓保证金和持仓浮盈。当前仅支持净持仓模式的 USDT 线性永续，其他产品、当前逐仓余额无法确认或历史字段不齐时保留近期复核结果并显示原因。历史强平成交按原始数量和实现盈亏处理，期初已持有且随后强平的仓位可逆推数量与成本。

## 统一分析日期

顶部提供一个月、三个月、半年、一年、全部历史和自定义起止日，按北京时间自然日包含起止两天。预设截至最新可用日收盘，以相同截止日期比较不同区间；点击预设立即计算，自定义需点击“应用日期”。切换日期使用已保存的逐笔数据即时重算，无需重新采集 API；“同步 API”负责补齐最新记录。

净盈亏 = 区间内平仓毛盈亏 + 手续费 + 资金费 + 其他调整。月份和合约统计来自同一批日期内账单。成交与胜率分别核对其数据覆盖；胜率只计开仓和平仓均在日期内的完整轮次，跨期与未平仓轮次不参与。当前权益、持仓浮盈及敞口单独标为实时快照，不回算成历史持仓。

风险重新使用日权益与外部划转估值计算；起始日前一日收盘仅用于首日收益分母，净值基准为 1，回撤高点在区间内重新建立。缺失日、非正权益与无效收益会断开连续段，仅对最后一段有效日收益计算夏普和回撤，并显示实际有效日期。样本不足、标准差为零、零轮次或缺少账单时显示“—”；完整覆盖但没有交易的区间允许显示零盈亏。导出包含分析日期、覆盖状态、对应明细及注明时点的当前快照；chartHistory 单独保存全历史图表序列及范围。

日期计算检查：`node account-dashboard/test_period.cjs`。后端合并与轮次复核：`python3 -m unittest discover -s account-dashboard -p 'test_*.py' -q`。

### 保存日期与自动到今天

完成日期修改或点击时间预设后，分析日期偏好自动保存于当前浏览器 localStorage（仅日期、预设及结束日期模式，不包含凭据）。刷新页面或重新打开同一地址会恢复。勾选“结束日期始终到今天”后，可固定开始日期，结束日期按北京时间每天更新；取消勾选可指定固定结束日期。今日盈亏只累计至最近成功同步时点，日净值与风险仍计算到最后已确认收盘，页面显示两者范围。示例模式不覆盖真实账户已保存偏好；浏览器禁止存储或清除站点数据后，无法持久保留设置。

## 回撤口径与资金流收益估算修正

默认回撤图使用账户权益相对此前权益高点的百分比：E / max(E) - 1，和权益曲线一致。展示最新日回撤及历史最大回撤，两者含义不同；转入与转出会影响此口径，不能将其当作纯投资业绩。缺失权益日会断开连续段，零权益可以显示 -100%。选择“资金调整净值回撤（估算）”则使用剔除本金流影响的净值序列，入金不能抹去此前亏损。上方投资净值风险卡片明确采用资金调整口径。

修正旧日收益公式的缺陷：旧版 (期末权益 - 净划转) / 期初权益 - 1 忽略新资金在当天参与交易的时间，残余余额极小再入金时会产生异常大收益率。现用 Modified Dietz 日估算：(期末 - 期初 - 净划转) / (期初 + 时间加权划转)，每笔权重为当天剩余秒数占比，按 UTC+8 计算。非 USDT 划转仍按日收盘估值。未取得每笔大额划转时的独立账户估值，因此这是估算而非精确 TWR，不宣称符合 GIPS；大额资金流与波动日附近仍可能有误差。旧缓存缺少加权输入的划转日不沿用旧收益率，等待同步更新。

公式参考：https://www.gipsstandards.org/wp-content/uploads/2021/03/gips-handbook-3rd-edition.pdf 。余额接近零后中午入金、权益创新高恢复回撤、零权益与缺口已纳入回归检查。

## 看板界面布局

桌面概览按“日期筛选 → 区间表现 → 当前账户快照 → 权益与风险 → 合约与交易明细”排列。五项区间指标独立显示，当前快照采用紧凑栏；权益和回撤为等宽卡片，控件、摘要和图表对齐。日期覆盖、全历史重建状态及回撤计算说明保留在可展开区域，待核对天数仍直接显示。手机宽度改为单列图表及两列表现指标。日期、回撤范围持久化及全历史图表规则保持原有功能。

## 登录期间的快照更新

账户连接且页面在前台时，每 30 秒调用只读快照接口更新资产、持仓、浮盈及敞口；后台暂停，返回后若已过刷新间隔则补一次更新。历史同步、导入与手动操作进行期间避让，失败保留旧快照并于下一周期重试。此机制不重复采集完整历史账单。金额变化采用 0.65 秒逐位滚动动画，首次加载及显示金额不变时不播放；遵循系统减少动态效果设置。

日期选择在完成修改后自动应用并保存，不再需要点击应用按钮；自动到今天选项立即生效。日期缺失或开始晚于结束时，保留上一有效分析区间并显示提示，错误输入不覆盖保存设置。

## 本地数据管理与复盘完善

顶部将快照时间、历史同步成功时间和最新记录时间分开显示。历史导入采用预览→确认两步，显示有效新增、重复记录、API 已覆盖及文件日期；旧导入批次没有当时的统计元数据时显示未知，不追溯伪造新增数。完整 API 与历史文件覆盖区间按来源合并显示。

新增当前账户历史备份与合并恢复：JSON 版本 1，包含原始记录、成功覆盖窗口、导入批次/明细、同步元数据与分析缓存，不含 API 凭据，也不包含其他账户或全局行情缓存。SHA-256 用于文件损坏检测，不是身份认证或数字签名。恢复必须连接对应账户，先预览归属、记录数及重复情况；事务合并，不覆盖已存在记录，随后重新同步复核。当前文件上限 22 MB，适合本地小规模账户。连接入口可离线打开备份，只读取文件内缓存，不显示当前快照，也不联网验证真实性；缓存没有完成分析时需连接账户恢复复核。备份包含私有交易信息，应按本机账户文件保管。

成交支持产品、买卖、来源筛选以及时间/盈亏/费用排序；买卖不等于开平仓。轮次详情展示毛盈亏、手续费、资金费、其他调整与净盈亏；多空汇总包括完整轮次样本、胜率、平均盈亏、持仓时间及最大连续亏损，跨期轮次不参与汇总。未完成覆盖时只展示记录，不给出完整汇总结论。

## Windows 账户保存

在 Windows 的普通已登录用户会话运行 `python account-dashboard/server.py`，打开 `http://127.0.0.1:4180/`。填写三项 API 凭据，勾选“记住此账户（保存在本机 Windows 凭据管理器）”，验证只读权限成功后才保存。下次打开会自动恢复并重新验证。

凭据为当前 Windows 用户的通用凭据（CRED_TYPE_GENERIC），采用 CRED_PERSIST_LOCAL_MACHINE，在同一用户后续登录仍保留，不跨设备漫游。不使用浏览器密码保存、明文文件或命令行传递秘密，无需安装第三方 Python 包。可在 Windows“凭据管理器 → Windows 凭据 → 普通凭据”中找到 `com.hengliang.okx.*` 条目。项目目录参与条目命名，移动项目目录后需要重新保存；旧目录的条目不会自动迁移。

断开连接保留凭据；“忘记账户”删除本项目保存的凭据，并保留历史数据库。受 Windows 单条凭据 2560 字节限制，过大的三项凭据会明确拒绝保存，仍可取消勾选，仅在当前会话使用。系统存储不可用时不会退回明文文件。

本次在 macOS 验证了 Windows API 模拟测试及原 Mac 保存/恢复回归：40 项测试中 39 项通过，1 项 Windows 原生测试因环境跳过。Windows 用户可运行 `python -m unittest discover -s account-dashboard -p test_windows_credentials.py` 验证真实系统 API；该测试只使用独立假数据条目并清理，不访问 OKX。当前没有 Windows 真机验收结果。
